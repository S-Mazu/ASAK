## 2026-08-06

- **M1 — Skeleton + First Feature**: shipped and live-tested, no bugs found.
- **FF#1 — Menu Shell**: `ASAK.ps1` entry point, `#requires -RunAsAdministrator` elevation guard, dot-sources `Functions\`, text menu loop.
- **FF#2 — Installed Apps & Features Inventory**: split into three functions during implementation — `Get-InstalledApp` (multi-select across Registry, Win32_Product, Package, Winget, tagged by source), `Get-InstalledFeature` (single-select between `Get-WindowsOptionalFeature` and `Get-WindowsFeature`), `Export-InventoryCsv` (toggleable NoTypeInformation/Encoding/Delimiter, unconditional export).
- **M2 — Menu UX Overhaul**: shipped and live-tested, no bugs found (one non-bug: `docs:` links stay plain-text since the test machine runs the legacy `conhost.exe`, which has no clickable-link support regardless of setting — accepted as a known copy-paste fallback).
- **FF#4 — Paged onscreen output**: both inventory displays pipe through `Out-Host -Paging`.
- **FF#5 — Clear screen on layer transitions**: broader than the original "on start" wording — clears on launch and on every top-menu ↔ submenu transition, not while staying inside a submenu's own loop.
- **FF#6 — Explain app sources in menu**: `Show-AppsMenu` states what each source actually returns (not just behavior), each with an MS Learn link — corrected mid-milestone after research showed the original draft mischaracterized `Package` (PowerShell/NuGet modules, not desktop apps) and `Winget` (broader than winget-only installs).
- **FF#8 — Two-level menu restructure**: top menu is `App Management` / `Version Info`; App Management is a flat submenu (Show/Export × Apps/Features); export tracks `$LastAppResult`/`$LastFeatureResult` separately.
- **FF#9 — Version Info menu item**: shows `$AsakVersion`, a short static usage summary, and points to `HISTORY.md` for release notes.
- **FF#10 — Default export path**: empty path prompt defaults to `.\<function name>.csv`.

## 2026-08-07

- **M3 — Sorting out Inventory**: shipped and live-tested; several bugs found and fixed during live-test (folded in below).
- **FF#3 — Get-AppxPackage integration**: `Appx` added as a fifth source to `Get-InstalledApp`.
- **FF#11 — Independent export collection**: Export now collects its own data via `Get-AppInventory`/`Get-FeatureInventory`/`Get-ModuleInventory`, no longer depends on `$Last*Result` from Show.
- **FF#34 — PowerShell module inventory**: new `Get-InstalledPSModule` function; sources `Module` (tagged by the literal `PSModulePath` segment it was found under) and `Package` (moved off `Get-InstalledApp` mid-milestone after live-test review confirmed it's PowerShell-only under PS7).
- **FF#35 — Split inventory into three top-level sections**: menu restructured to PowerShell Modules / Installed Apps / Windows Features / Version Info.
- Live-test fixes folded into M3: unreadable Modules table (`Format-Table -Wrap`), `Q`-quit paging error (try/catch on `OperationStopped`), `Source` column moved last for Modules/Packages, friendlier Optional/ServerManager feature-query failure message, 30-second background-job timeout on feature queries (`Get-WindowsOptionalFeature`/`Get-WindowsFeature` can hang on a broken DISM COM registration).

## 2026-08-21

- **M4 — Basic winget integration (PoC)**: shipped and live-tested, no bugs found.
- **FF#36 — Winget quick-install for common apps**: new top-level menu item "Software Install" > "Winget", curated list of Docker Desktop (`Docker.DockerDesktop`), Claude Code (`Anthropic.ClaudeCode`), VLC Player (`VideoLAN.VLC`), Chrome Browser (`Google.Chrome`) — all four winget IDs verified via `winget search` before implementation. Four new functions (`Test-WingetAppInstalled`, `Install-WingetApp`, `Update-WingetApp`, `Uninstall-WingetApp`) — the first `SupportsShouldProcess`/`ShouldProcess()` functions in the repo — use `$LASTEXITCODE` from `winget list --id <Id> --exact` rather than text parsing to check install status. Folded in during the same session: uninstall now checks whether the app's process is running (`Test-ProcessRunning`, new function) and asks a second confirmation before proceeding if so; skipped for Claude Code, which has no single reliable process name to check.
- **M5 — Expand winget curated app list (Round 2)**: shipped and live-tested.
- **FF#37 — Expand curated winget app list**: added Gimp (`GIMP.GIMP`), Teams for Business (`Microsoft.Teams`), OneDrive for Business (`Microsoft.OneDrive`), Git for Windows (`Git.Git`), Claude Desktop App (`Anthropic.Claude`), Spotify (`Spotify.Spotify`), Irfanview (`IrfanSkiljan.IrfanView`) — 7 apps, same install/upgrade/uninstall flow as FF#36. Live-tested: Gimp and Irfanview installed for real and confirmed present; the other apps checked read-only (Claude Code, Teams, OneDrive, Git, Claude Desktop App already installed on the test machine; Docker Desktop, VLC, Chrome, Spotify were not). Adobe Acrobat Reader (`Adobe.Acrobat.Reader.64-bit`) was also tried during live-test and dropped: `winget install` reports success (exit 0, "Erfolgreich installiert") but the Adobe bootstrapper only extracts its MSI payload and never runs the actual install — no registered app, no Program Files entry. Not pursued further; leftover extracted files were deleted from the test machine, and the entry was removed from the curated list entirely.
- **FF#38 — PowerShell 7 upgrade-only via detached process**: `Update-WingetApp` gained a `-Detached` switch — runs `winget upgrade` via a spawned `cmd.exe` process instead of in-process. Curated-app data gained `UpgradeOnly`/`DetachedUpgrade` flags; `Invoke-WingetAppAction` uses them so the PowerShell 7 entry only ever offers Upgrade, never Install or Uninstall. Live-tested via `-WhatIf` and a real (non-mutating) install-status check; not upgraded for real during this test.
- **Bugfix — `Update-WingetApp` false "upgrade failed" for already-current apps**: `winget upgrade` exits a distinct non-zero code (`0x8A15002B`, "no applicable upgrade found") when a package has nothing to upgrade — the old `$LASTEXITCODE -eq 0` check treated this the same as a real failure. Reported by the user for Claude Desktop App; reproduced directly against the real app to confirm the exact exit code. Fixed by changing `Update-WingetApp`'s return from `[bool]` to a status string (`Upgraded`/`UpToDate`/`Failed`/`Skipped`); `Invoke-WingetAppAction` now shows "already up to date" instead of a false failure warning. `Install-WingetApp`/`Uninstall-WingetApp` left as `[bool]` — they're only ever offered when the app's install state is already known, so they have no analogous no-op-success case.

## 2026-08-24

- **FF#39 — Add Notepad++ to curated apps**: added Notepad++ (`Notepad++.Notepad++`) to `Script:WingetCuratedApps`. Live-tested.
- **FF#40 — Bulk-upgrade winget apps**: new `Get-WingetUpgrade` function enumerates pending winget upgrades, parsed by column position rather than header text since winget localizes column headers to the OS locale (observed: `Available`→`Verfügbar` on German-locale Windows — ADR-008). New `Invoke-WingetBulkUpgrade` orchestrates the upgrade loop behind a single batch-level `ShouldProcess` gate rather than per-app (ADR-009). ## 2026-08-26

- **FF#41 — Show all winget managed items**: new `Show-WingetPendingMenu` lists pending winget upgrades (Name/Id/Version/Available) via `Get-WingetUpgrade` without upgrading anything. Reuses `Select-WingetUpgradeScope`, so it offers the same Curated/All choice as the bulk upgrade, and pages through `Out-Host -Paging` with the same `OperationStopped` guard as the inventory displays. Wired into the Winget submenu as an `S` choice alongside the existing `B`.
- **BUG#1 — `Get-InstalledApp` Winget source drops Publisher on non-English Windows**: the `Winget` branch keyed its fields off the literal English header text, which winget localizes. Fixed by extracting the fixed-width parser both winget callers had duplicated into one `ConvertFrom-WingetTable`, reading fields by column position and padding every row to the header's column count (ADR-010, supersedes ADR-008). `Get-InstalledApp` and `Get-WingetUpgrade` both consume it. `winget list` carries no publisher data at all — its `Source` column names the package source (`winget`/`msstore`) — so `Publisher` is now deliberately empty for Winget-sourced rows instead of carrying that mis-mapped value. Two defects surfaced during implementation and were fixed: `[Parameter(Mandatory)]` on a `[string[]]` applies per-element non-empty validation, so blank lines in real winget output failed parameter binding (`[AllowEmptyString()]`); and `Write-Output -NoEnumerate` tripped `PSUseCmdletCorrectly` (named `-InputObject` explicitly rather than suppressing). Verified read-only against real output on the test machine: 217 rows, no blank names or versions, `Get-WingetUpgrade` unchanged at 22 pending upgrades. Note: on this machine's current winget build both `winget list` and `winget upgrade` print English headers despite a `de-DE` system locale, so the bug was latent rather than actively firing when fixed.

## 2026-08-28

- **BUG#2 — winget bulk upgrade produced no output**: `Show-WingetBulkUpgradeMenu` gave no sign of life between the scope prompt and the final table, so a running batch was indistinguishable from a hang. It now prints scope, count and the numbered app list before starting, and pipes `Invoke-WingetBulkUpgrade` through `ForEach-Object` instead of assigning it, so each app reports the moment it finishes rather than only after the whole batch; a summary line precedes the result table. Progress output stayed in `ASAK.ps1` — no file in `Functions\` writes to an output stream (ADR-001). One trap caught during implementation: `switch` rebinds `$_` to its own input inside case blocks, so the pipeline object has to be held in a variable or every progress line prints an empty name. Nothing prints during an individual app's winget run, which is why the app list goes up front.
- **BUG#3 — `Failed` hid the winget exit code**: `Update-WingetApp` collapsed every code except `0` and `-1978335189` into `Failed`, leaving reboot-required, another-install-in-progress and package-not-found indistinguishable — the drawback ADR-004 named in advance. It now returns `[PSCustomObject]@{ Result; ExitCode }` (ADR-011, supersedes ADR-007); the failure warning and the bulk result table both carry the code. Both call sites adapted, in `Invoke-WingetAppAction` and `Invoke-WingetBulkUpgrade`.
- **BUG#4 — `ShouldProcess` gated twice on bulk upgrade**: `Invoke-WingetBulkUpgrade` gated the batch and `Update-WingetApp` gated again per app, so `-Confirm` asked once for the batch and then once for every app. The batch call now passes `-Confirm:$false` (ADR-012, amends ADR-009); the nested gate stays in place for `Invoke-WingetAppAction`, where it is the only one.
- **Verification note for BUG#2/#3/#4**: `tools/verify.ps1` clean — zero PSScriptAnalyzer findings, Pester 50/50 — and the bulk path checked under `-WhatIf`. Not live-tested at the time of this commit; the real upgrade run follows in a fresh shell.
- **Live test for BUG#2/#3/#4**: the real bulk upgrade run confirmed the banner, per-app progress lines, summary and `ExitCode` column. Bugs closed.

## 2026-08-29

- **M6 — Quick Wins**: seven read-only information features shipped together behind a new `System Information` top-level menu (`Version Info` moved from `5` to `6`). Nine new functions, all read-only — the first ASAK work that changes no machine state, so none declares `SupportsShouldProcess`. `$AsakVersion` 0.3.0 → 0.4.0.
- **FF#12 — Show Windows license key**: `Get-WindowsProductKey` reads the firmware/OEM key from `SoftwareLicensingService.OA3xOriginalProductKey`, and edition, channel, `PartialProductKey` and license status from `SoftwareLicensingProduct` filtered to the Windows application ID. An empty firmware key is a valid result on retail installs and virtual machines, not a failure. The registry `DigitalProductId` blob is deliberately not decoded: on current Windows it yields a generic placeholder key, which is worse than an empty field.
- **FF#13 — Get Autopilot hardware hash**: `Get-AutopilotHardwareHash` reads `DeviceHardwareData` from `MDM_DevDetail_Ext01`, the serial from `Win32_BIOS` and the product ID from the registry. It returns exactly three properties named `Device Serial Number`, `Windows Product ID` and `Hardware Hash` — the literal Intune import headers — and throws rather than carrying an error field, because a fourth column makes the exported CSV unimportable. Its export bypasses `Invoke-ExportPrompt` and forces a comma delimiter; Intune rejects the menu's default `;`. Reading the hardware data requires elevation, which ASAK already has.
- **FF#19 — Get Intune enrollment status**: `Get-IntuneEnrollment` picks the `HKLM:\SOFTWARE\Microsoft\Enrollments` key whose `ProviderID` is `MS DM Server` with `EnrollmentState` 1, and adds the MDM device certificate's thumbprint and expiry. The other keys under that hive — Local, Cloud and Deploy Authority, and the SCCM WMI bridge — exist on unmanaged machines too, so the provider name is what identifies the enrollment.
- **FF#20 — Local admin group members**: `Get-LocalAdministrator` resolves the group by well-known SID `S-1-5-32-544`, never by its name, which Windows localizes. Members whose name is still a raw SID are flagged `IsUnresolved` — an orphaned AzureAD or domain grant worth noticing. `ObjectClass` is localized as well (observed: "Andere"), so no logic keys off it.
- **FF#22 — Windows version check**: `Get-WindowsVersion` compares the local build against endoflife.date and `Get-PendingWindowsUpdate` scans the Windows Update Agent for the patch level, because neither source answers both halves of the question (ADR-013). The scan runs inside a 300-second background-job deadline in the menu, the same treatment the feature query gets (ADR-003), and sits behind its own prompt since it is the only slow path in the menu.
- **FF#23 — SCCM vs Intune management status**: `Get-ConfigMgrClient` decides ConfigMgr presence by whether the `root\ccm` namespace answers, not by the Enrollments registry, which reports a false positive (ADR-014). `Get-DeviceManagement` composes it with `Get-IntuneEnrollment` into `CoManaged` / `Intune` / `ConfigMgr` / `None`. Domain and Entra join state stay out — that is FF#24.
- **FF#33 — Network stats**: `Get-NetworkConfiguration` returns one row per adapter from `Get-NetIPConfiguration -Detailed -All`. Virtual, Bluetooth and disconnected adapters are kept — filtering them would also hide a misconfigured NIC — with `Status` showing which one is live. A disconnected adapter reports its addresses as `$null` on some fields and as an empty array on others, and neither survives a bare member access under `Set-StrictMode`, which `tools/verify.ps1` applies to the whole Pester run.
- **Housekeeping — `Get-RegistryValue`**: new shared helper behind four call sites. `Get-ItemPropertyValue` writes a non-terminating error for a missing value and ignores `-ErrorAction SilentlyContinue`, so enumerating the Enrollments keys printed five errors per call. Reading the whole property bag and picking the value out via `PSObject.Properties` returns `$null` instead, and survives `Set-StrictMode`.
- **Verification**: `tools/verify.ps1` clean — zero PSScriptAnalyzer findings, Pester 95/95, up from 50. Every function was confirmed against real machine data, and the menu was manually tested including the elevated Autopilot and MDM-certificate paths.
